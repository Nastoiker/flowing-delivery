# Уведомления о заказах

API отправляет событие `newNotification` с полями `id` (UUID), `type`, `message`, `createdAt` (ISO UTC). Клиент передаёт JWT через `auth.token` при подключении Socket.IO. Старый формат со строкой сообщения и токеном в query больше не используется: backend и frontend нужно обновлять вместе.

После проверки JWT сервер присоединяет соединение к комнате `user_<id>`. Все вкладки пользователя получают одно событие с одинаковым ID. Отключение одной вкладки не удаляет остальные соединения. Socket.IO автоматически освобождает комнату при disconnect: [документация rooms](https://socket.io/docs/v4/rooms/).

Панель справа показывает время и непрочитанные записи, позволяет прочитать отдельное уведомление, прочитать все или очистить историю. Счётчик отражает только непрочитанные записи. Последние 100 записей сохраняются в localStorage отдельно для каждого пользователя; изменения синхронизируются между вкладками через storage events. Если localStorage недоступен, история работает в памяти. Переподключение не зависит от обновлений объекта профиля или корзины.

При создании заказа уведомляются покупатель и администраторы, при изменении статуса — покупатель. Ошибка отправки после успешной операции логируется и не превращает её в ошибку для клиента.

## Границы гарантий

- Это доставка онлайн без подтверждений и серверной истории. События, отправленные во время отключения, не восстанавливаются. Для гарантированной доставки необходимы transactional outbox и серверный inbox.
- История привязана к браузеру и аккаунту, не синхронизируется между устройствами и остаётся на устройстве после выхода. Очистить её можно кнопкой в панели или удалением данных сайта.
- Для нескольких реплик API нужен общий Socket.IO adapter. Текущая конфигурация рассчитана на одну реплику API.

## Проверка

`npm run test:api` в `delivery-service` проверяет маршрутизацию в пользовательские комнаты, дедупликацию адресатов, авторизацию соединения, отклонение некорректных токенов и сохранение успешного ответа при сбое уведомления. Этот набор запускается в GitHub Actions.

Для ручной проверки открыть приложение в двух вкладках одного аккаунта, создать заказ и проверить обе панели. Закрыть одну вкладку, изменить статус заказа и проверить оставшуюся. Прочитать уведомление, обновить страницу: отметка должна сохраниться. Отключить сеть: панель должна показать отсутствие соединения.
